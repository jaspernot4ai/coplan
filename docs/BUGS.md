## BUG-001：人按下結帳，稽核紀錄卻標成 Agent ✅ 已修

**發現時間**：2026-08-28
**嚴重度**：高（不影響功能，但破壞稽核可信度——而稽核正是本作品的核心主張之一）

### 症狀

使用者自己按下畫面上的「結帳」按鈕，Agent 活動時間軸卻把該筆記錄顯示為
「🤖 Cindy 的 Agent request_checkout」。

### 成因

`src/index.js` 第 176 行附近，`request_checkout` 分支的 `addLog` 把 `viaAgent` 寫死為 `true`：

```js
this.addLog({
  who: msg.by,
  viaAgent: true,        // ← 寫死，忽略了呼叫端傳來的值
  action: "request_checkout",
  ...
});
```

前端的 `requestCheckout(viaAgent)` 其實已經正確傳值（人按按鈕傳 `false`、
WebMCP 工具傳 `true`），但後端沒有採用。

### 修正

```js
viaAgent: msg.viaAgent,
```

### 驗收

1. 自己按畫面上的「結帳」→ 時間軸顯示 🙋（人）
2. 對 Agent 說「幫我結帳」→ 時間軸顯示 🤖（Agent）

### 這個 bug 的教訓

程式做對了事，但**記錄說了謊**。功能測試不會發現它，因為結帳流程本身完全正常。
它之所以被抓到，是因為稽核資訊直接顯示在畫面上——這反過來證明了
「把稽核攤開來給人看」是好設計：它讓錯誤自己現形。

同類風險：任何寫死的 `viaAgent`、`who`、`action` 都要檢查是否應該來自呼叫端。
**稽核欄位一律取自呼叫端傳入的值，不可在記錄處自行假設。**
