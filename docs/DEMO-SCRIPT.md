# CoPlan Demo 影片腳本（3 分鐘以內，硬性規定）

> 評審四項等權重標準：WebMCP 運用深度 / 執行品質 / 潛在影響 / 創意與野心。
> 這支影片要在三分鐘內，讓每一項都有一個明確的畫面對應。

## 核心敘事

**一句話**：三個人各自帶著自己的 AI Agent，一起編輯同一份行程表；
系統即時標出衝突讓人裁決；而花錢那一步，Agent 永遠按不下去。

**不要**做成功能導覽（「這裡可以新增、這裡可以刪除…」）。要做成一個**故事**：
一群朋友要去東京，Agent 幫忙排，排出了衝突，人解決，最後要付錢時系統把 Agent 擋下來。

## 錄影前的準備

1. `npx wrangler deploy`，確認線上版是最新的
2. 開一個乾淨房號，例如 `tokyo-demo`
3. **兩個視窗並排**（螢幕左右各半）：
   - 左：ChatGPT 桌面版，內建瀏覽器開 `https://coplan.coplan-lab.workers.dev/r/tokyo-demo?as=Cindy`
     （模型必須是 GPT-5.6 Sol 或 Terra，Luna 不支援 WebMCP）
   - 右：Chrome，開 `https://coplan.coplan-lab.workers.dev/r/tokyo-demo?as=Bob`
4. 兩邊都確認顯示「WebMCP 已就緒」與「已連線」
5. Cindy 先設好預算 10000（避免影片浪費時間在設定上）
6. 螢幕錄影軟體：OBS 或 Windows 內建 Win+G

**注意**：目前只有一個 Agent 可用（ChatGPT 桌面版）。
Bob 那一側由人手動操作即可——這反而更能演出「人和 Agent 同框」。
旁白說明「每位成員都可以帶自己的 Agent」，畫面演示其中一位帶 Agent 的情況，不算誇大。

## 分鏡

### 0:00–0:15　開場（問題）

**畫面**：兩個視窗並排，同一份空行程表，兩個名字在成員列上。

**旁白**：
> 「三個朋友要去東京。他們各自有 AI Agent，但今天的 Agent 只能各做各的——
> 它們沒辦法一起編輯同一份行程。CoPlan 用 WebMCP 改變這件事。」

### 0:15–0:50　Agent 開始工作（WebMCP 運用深度）

**操作**：在 ChatGPT 說
> 「幫我看看目前的行程，然後第一天早上安排築地市場，中午找一間壽司店。」

**畫面重點**：
- ChatGPT **先呼叫 `list_itinerary`** 才動手（它會說「目前行程是空的」）
- 右邊 Bob 的視窗**同步冒出行程卡片**，標著 🤖
- 右欄時間軸逐筆記錄工具呼叫

**旁白**：
> 「Agent 不是在猜按鈕位置、也不是在模擬點擊。這個網頁用 WebMCP 直接把
> 六個工具宣告給它——它讀了現況才動手，而且每一次呼叫都留下紀錄。」

### 0:50–1:20　人加入，衝突浮現（創意與野心）

**操作**：在 Bob 的 Chrome 視窗**手動**新增一筆「淺草寺 09:00–11:00」（與築地市場衝突）

**畫面重點**：
- 兩張卡片同時變成琥珀色，顯示「⚠️ 與其他 1 個行程時間重疊」
- 兩個視窗**同時**變色
- 時間軸出現 🙋 Bob 的紀錄，與 🤖 的紀錄並列

**旁白**：
> 「Bob 手動加了一個景點，和 Agent 排的撞了時間。衝突偵測是純程式邏輯——
> 不呼叫模型、不會幻覺、毫秒內就標出來。但系統不會替他們決定，
> 它只是把問題攤開，讓人來裁決。」

### 1:20–1:45　人裁決（執行品質）

**操作**：在 Bob 的視窗直接把淺草寺改成 `14:00–16:00`

**畫面重點**：
- 琥珀色**同時**在兩個視窗消失
- ChatGPT 那一側的畫面也跟著更新

**旁白**：
> 「人改一個時間，兩邊同時恢復正常。人和 Agent 走的是同一條程式路徑——
> 沒有給 Agent 開後門，所以他們看到的永遠是同一份真相。」

### 1:45–2:40　付款閘門（潛在影響 —— 全片高潮）

> **這一段已按「綁裝置＋綁本人」的新設計重寫（第二次重寫）。**
> 第一版腳本寫的是「Agent 按不下去」——實測發現 ChatGPT 內建瀏覽器可以直接點按鈕，
> 那個版本是假的，改成「發起請求的分頁根本不渲染確認按鈕」。
> **這個第二版後來也被自己實測破解**：確認條件只看 `sessionId`（每次載入頁面都重新產生、
> 不存 localStorage），結果「同一個瀏覽器開新分頁」在伺服器眼中就是全新的 session，
> ChatGPT 桌面版被要求「開新分頁按確認」時真的照做，付款照樣完成。而且舊版完全沒檢查身分，
> 任何旅伴都能確認別人的付款。現在的規則是兩條都要滿足：**確認者是不同裝置，而且是本人**——
> 旅伴看得到待確認、能取消，但確認按鈕不會出現。確認必須來自本人自己的另一台裝置
> （手機，或另一個瀏覽器 profile）。

**錄影前額外準備**：手機也開好同一個房間網址（`?as=Cindy` 同一個名字即可），
螢幕錄影要能拍到手機——**手機拿在鏡頭前實拍最有說服力**，
若不方便，用手機投影到電腦畫面也可以。

**操作**：
1. 事先在幾筆行程填好價格，讓總額超過預算
2. 在 ChatGPT 說「幫我把這些訂起來，結帳」
3. Agent 呼叫 `request_checkout`
4. **鏡頭停在電腦畫面 3 秒**，讓觀眾讀完那段文字
5. 拿起手機，畫面上按下 Approve payment
6. **鏡頭切回電腦**：卡片同時轉為 ✅ Paid，時間軸多一筆確認紀錄

**畫面重點**（這段是全片最重要的 20 秒，節奏要慢）：

- 電腦上出現待確認框：`Cindy's Agent requested checkout of NT$12,000 ⚠️ Over budget limit`
- **下面這兩行要清楚可讀，是全片的論點**：
  > 🔒 For your protection, the device that requested this payment cannot approve it.
  > Open this room on your phone or another device, or ask a fellow traveler to approve.
- 電腦上**只有 Cancel this request，沒有 Approve payment**——
  可以用滑鼠在那個位置停一下，讓觀眾注意到「那顆按鈕不在」
- ChatGPT 那側會說它無法完成付款、請使用者去另一個裝置確認——**把這段對話框入鏡**
- 手機按下確認的瞬間，電腦畫面同步變化

**旁白**：
> 「最後一步是花錢。Agent 可以查價、湊單、把整筆訂單準備好——但它按不下確認。
>
> 而且這不是把按鈕設成 disabled 就算數。一個能操作瀏覽器的 Agent 點得到任何存在的按鈕，
> 而它注入的點擊事件 isTrusted 是 true，跟真人無法區分。第一版就是這樣被我們自己戳破的。
>
> 所以確認按鈕在請求端的分頁裡根本不存在。但我們後來發現光是『另一個分頁』還不夠——
> 同一個瀏覽器開新分頁，看起來就像是不同的一次連線。所以現在確認條件是兩條：
> 必須是不同裝置，而且必須是本人自己。旅伴看得到這筆請求、能取消，但按不下確認——
> 只有 Cindy 自己的另一台裝置可以。」

**⚠️ 這裡不要用「第二個瀏覽器視窗當 Bob」當備案**——舊版才會讓 Bob 確認成功，
現在的規則下 Bob 這個名字**一定會被伺服器擋下**，錄到一半按不下去，反而穿幫。

**（若手機實拍太難，正確備案）**：開第二個瀏覽器視窗或無痕視窗，網址用**同一個名字**
`?as=Cindy`（不是 Bob）——模擬 Cindy 自己的第二台裝置。旁白改成「或是用自己的另一個瀏覽器、
另一台裝置，一樣是本人親自確認」。效果略遜於手機實拍，但仍完整成立，而且是唯一真的會成功的備案。

### 2:35–2:55　收尾（論述）

**畫面**：拉遠，三欄版面全景——左邊成員與預算、中間行程、右邊完整的活動時間軸。

**旁白**：
> 「所有 Agent 動作都在這條時間軸上，誰做的、什麼時候、動了什麼，
> 一目瞭然。CoPlan 沒有自己的 Agent——每個人帶自己的來。
> 網站要做的，只是把能力誠實地開放出去，然後把該留給人的決定留給人。」

**最後一秒**：畫面留在網址與「WebMCP · Cloudflare Durable Objects」字樣。

## 剪輯注意事項

- **總長必須低於 3:00**，超過會被扣分甚至不予評分。目標 2:55。
- Agent 思考時要**加速播放**（2–4 倍），但**不要剪掉**——評審要看到它真的在呼叫工具。
  加速時畫面右下角標「×3」。
- 每個關鍵畫面**停留至少 2 秒**，特別是紅框那句「Agent 無法自行完成付款」。
- 字幕用英文（評審是國際評審），旁白可用中文配音或直接不配音只放字幕。
  **若時間有限，字幕優先於配音。**
- 不要加背景音樂蓋過內容；若要加，音量壓到很低。
- 不要放片頭動畫，第一秒就進入畫面。三分鐘很短。

## 若時間不足的取捨順序

必留：付款閘門（1:45–2:40）> Agent 呼叫工具（0:15–0:50）> 衝突與裁決（0:50–1:45）
可砍：開場旁白縮短到 8 秒、收尾縮短到 12 秒。
